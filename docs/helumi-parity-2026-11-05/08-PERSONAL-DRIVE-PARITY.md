# What matches Helumi on this Mac?

Status: November 6, 2026. CloudDrive build 45 is installed in Applications. Its regression run passed 514 tests (340 app, 9 adapter and 165 core). The personal R2 drive reconnected after normal eject and relaunch. All 11,845 original paths and sizes matched the inventory; three independent content digests matched through the mount. The running owner's engine digest matched the installed engine and all personal revisions were published at inspection.

| Behavior | What we can say |
|---|---|
| Group existing folders in Finder | Tested the literal Finder command on both apps: 12 folders, 765 descendants. Build 45 took 1.124 s, Helumi 1.266 s. Both retained the expected 765 file records. The [grouping report](evidence/native-finder-grouping-build45.json) includes independent R2 verification; the generated R2 scope was removed and relisted empty. One pair of timings does not imply either is always faster. |
| Copy a Logic project | A generated package containing 12 files in 24 nested directories took 1.849 s on build 44. Two warm Helumi samples took 1.295 and 1.445 s. All 12 file hashes matched. That tests Finder copying, not every Logic plug-in or save workflow. |
| Copy a new large file | On a normally provisioned Mac disk, a dense 224 MiB file took 3.372 s through Finder on build 45 and 0.535 s on Helumi. Both mounted readbacks matched the input hash. An independent R2 lookup from the published directory by filename and full remote readback also matched. This is a material remaining speed difference. |
| Work during a pending upload | Two independent moves succeeded on a mounted build 45 volume while publication was paused. This does not establish arbitrary overlapping moves or recursive merge/replace conflict policy. |
| Normal files and folders | Mounted build 45 passed create, write, flush, read, rename, remove, open-reader survival after unlink, and atomic replacement with outstanding open handles. These are CloudDrive functional checks, not a side-by-side comparison of every Finder command. |
| Keep downloaded, free space, tags | Pinning and freeing changed the reported availability on the real mount; native Finder tag bytes survived rename and could be removed. This does not verify all Finder badge rendering or all third-party metadata. |
| Transfers larger than available local space | A real 224 MiB file reached R2 from Finder on build 45 with the entire working volume hard-limited to 160 MiB. Finder took 27.946 s, peak space used was 47.16 MiB, and the independently downloaded hash matched by 86.762 s. See the [constrained-volume record](evidence/native-finder-hard-cap-build45.json). Finishing Finder's copy and finishing R2 publication are separate events. No hundreds-of-gigabytes physical transfer was performed. |
| App controls | Name/path search, activity, transfer limits, Recently Deleted/restore, and optional encrypted managed storage have feature tests, including earlier installed builds. Encrypted cold recovery was tested on generated storage. Exact Helumi UI, shortcuts, trash retention, and recovery semantics were not demonstrated. |
| Known boundaries | Single writing Mac. Native symbolic- and hard-link creation are unsupported. No full-content Spotlight index. Recursive merges into populated folders, every editor, long sleep/wake and power loss remain unqualified. Sharing and file requests are intentionally excluded. |
